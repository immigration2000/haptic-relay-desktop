# Haptic Relay 전체 목업 UI 설계

## 목표

`C:\Users\user\Downloads\UI mockups needed`의 1180 x 780 목업을 현재 Electron 앱에 적용한다. 로그인, 서버 선택, 방 브라우저, 방 내부, 하드웨어, 보호, 로그 화면을 모두 제공하되 기존 릴레이·하드웨어 IPC 기능을 유지한다.

이번 단계는 프런트엔드 데모 계층을 완성하는 작업이다. 계정 서버, 공개 방 목록 API, 결제, 국가별 릴레이 자동 배정은 구현하지 않는다.

## 사용자 흐름

1. 앱을 실행하면 데모 로그인 화면을 표시한다.
2. 아이디와 비밀번호가 비어 있지 않으면 로그인에 성공한다.
3. 로그인 상태와 표시 이름을 로컬에 저장한다.
4. 로그인 후 역할 선택 없이 방 브라우저로 이동한다.
5. 사용자가 방을 만들면 호스트가 된다.
6. 사용자가 초대 코드 또는 실제 방 정보로 입장하면 참가자가 된다.
7. 샘플 방은 방 목록·검색·필터 확인용으로만 사용하며 데모 배지를 표시한다.
8. 실제 방에서는 기존 릴레이 서버와 Electron IPC를 사용한다.

## 화면 구조

### 로그인

- Haptic Relay 브랜드 영역
- 아이디, 비밀번호, 로그인 유지
- 비어 있지 않은 입력만 허용하는 데모 로그인
- 실제 비밀번호를 파일이나 로그에 저장하지 않음

### 공통 AppShell

- 상단 58px: 로고, 현재 서버, 서버 선택, Relay 상태, Device 상태, 하드웨어 설정, 사용자 프로필
- 중앙: 현재 화면 콘텐츠
- 하단 약 26px: 릴레이 상태, 최근 상태 메시지, 앱 버전
- 1180 x 780을 기준 크기로 사용
- 최소 960 x 640에서 가로 스크롤 없이 콘텐츠 재배치

### 서버 선택

- 국가별 데모 서버 2 x 5 목록
- 이름, 지연시간, 연결 상태 표시
- 사용자 지정 서버 모달
- 사용자 지정 URL은 기존 URL 검증 규칙을 사용
- 연결 테스트는 `/healthz` 또는 기존 방 API 호출 경계에서 오류를 표시
- 실제 릴레이 URL은 사용자가 선택한 사용자 지정 서버 또는 현재 기본 URL 사용

### 방 브라우저

- 검색, 정렬, 필터 탭
- 샘플 방 카드와 현재 세션에서 만든 실제 방 카드 구분
- 방 번호, 호스트, 업데이트, 썸네일, 소개, 태그, 인원, 서버, 입장 방식 표시
- `방 만들기`, `초대 코드로 입장`, `새로고침` 제공
- 샘플 방 입장 시 데모 상세 화면만 표시하고 실제 모션 연결은 만들지 않음

### 방 만들기

- 방 이름, 소개, 태그, 입장 방식, 비밀번호, 최대 인원, 대표 이미지 UI
- 실제 서버 요청에는 현재 지원되는 방 이름, 비밀번호, 입장 방식만 전달
- 소개, 태그, 최대 인원, 대표 이미지는 현재 앱 세션의 프런트엔드 메타데이터로 유지
- 성공하면 호스트 방 화면으로 전환

### 호스트 방

- 개요: 방 정보, 초대 코드, 접속자, 승인 대기
- 참가자 관리: 승인, 거절, 강퇴, 세션 차단
- 실시간 시연: 기존 30Hz 최신값 스트림과 위치·강도 제어
- 하드웨어: 기존 포트 탐색, 연결, T-Code 설정
- 보호: 로컬 및 방 전체 긴급 정지
- 로그: 기존 Electron 로그 필터와 내보내기

### 참가자 방

- 수신 모니터: 최신 위치, 강도, 프레임 상태
- 지연 설정: 기존 로컬 수신 지연
- 하드웨어: 기존 포트와 프로필 설정
- 보호: 강도 상한, 위치 범위, 수신 일시정지, 로컬 정지
- 로그와 방 나가기

## 컴포넌트 경계

- `App`: 화면 전환과 실제 세션 상태 조정
- `AppShell`: 공통 상단바, 본문, 하단 상태바
- `LoginView`: 데모 로그인 상태
- `RoomBrowserView`: 샘플·세션 방 탐색
- `HostRoomView`: 호스트 세션 화면
- `ParticipantRoomView`: 참가자 세션 화면
- `HardwareView`: 하드웨어 설정 UI
- `SafetyView`: 보호 및 긴급 정지 UI
- `LogsView`: 로그 필터와 내보내기
- `ServerSelector`: 서버 프리셋과 사용자 지정 URL
- `RoomDialogs`: 방 생성, 초대 코드, 비밀번호, 사용자 지정 서버 모달
- `demo-data`: 샘플 사용자, 서버, 방 데이터

화면 컴포넌트는 표시와 사용자 이벤트 전달을 담당한다. Electron IPC 호출과 방 세션 변경은 상위 조정 계층에서 수행해 기존 동작을 한곳에서 유지한다.

## 상태와 데이터 흐름

### 데모 UI 상태

- 로그인 사용자
- 로그인 유지 여부
- 서버 프리셋
- 샘플 방 목록과 필터
- 방 소개, 태그, 썸네일 같은 프런트엔드 메타데이터

데모 로그인 상태는 로컬 저장소에 저장할 수 있지만 비밀번호는 저장하지 않는다.

### 실제 기능 상태

- 방 생성·입장·퇴장
- 호스트와 참가자 토큰
- 승인·거절·강퇴·차단
- 모션 시연과 수신
- 하드웨어 포트·프로필
- 보호 설정과 지연
- 로그

실제 기능 상태는 기존 `window.hapticRelay` API와 Electron main process를 단일 진실 공급원으로 사용한다.

## 오류와 빈 상태

- 서버 연결 실패: 선택한 서버와 재시도 버튼 표시
- 사용자 지정 URL 오류: 입력 필드 아래에 검증 이유 표시
- 빈 방 목록: 검색 조건 해제와 방 만들기 동작 제공
- 샘플 방: `데모 데이터` 배지와 실제 연결 없음 표시
- 승인 대기: 참가자 화면을 대기 상태로 유지
- 하드웨어 미연결: 수신 정상과 장비 미연결을 분리 표시
- 릴레이 연결 해제: 상단 상태와 하단 상태바에 동시에 반영
- 긴급 정지: 일반 버튼과 구분되는 위험 색상과 확인 가능한 상태 사용

## 시각 규칙

- 제공된 `Industry` 토큰의 회색 표면, 청회색 강조색, Barlow 계열 타이포그래피 사용
- 카드 반경은 최대 4px, 모달은 최대 7px
- 장식용 그라데이션이나 원형 배경 장식은 사용하지 않음
- 방 브라우저는 카드보다 정보 비교와 빠른 입장을 우선
- 아이콘이 적합한 명령은 Lucide 아이콘을 사용하고 툴팁 제공
- 긴 문구는 줄바꿈하고 버튼·상단바 높이를 변경하지 않음
- 고정 헤더와 하단바 외 본문만 스크롤

## 반응형 동작

- 1180 x 780: 목업의 전체 열과 카드 정보 표시
- 960 x 640: 썸네일과 보조 메타 열 축소
- 더 좁은 너비: 방 카드를 2열 정보 구조로 재배치하고 상단 시스템 상태를 축약
- 가로 드래그나 페이지 전체 가로 스크롤은 허용하지 않음

## 검증

- TypeScript 타입 검사와 전체 빌드
- 로그인, 방 브라우저, 서버 선택, 모달 전환 UI 자동 테스트
- 방 생성 후 호스트 화면 전환
- 초대 코드 입장 후 참가자 화면 전환
- 승인형 방의 대기·승인 흐름
- 로컬 패키지 2클라이언트 30Hz 수신 테스트
- 휴대폰 Quick Tunnel 외부 서버 패키지 2클라이언트 테스트
- 1180 x 780, 960 x 640 화면 캡처와 오버플로 검사
- 앱 종료 후 `Object has been destroyed` 회귀 검사

## 완료 조건

- 제공된 목업의 주요 화면이 모두 로컬 Electron 앱에서 이동 가능하다.
- 실제 방 생성·입장·30Hz 시연·수신 기능이 유지된다.
- 샘플 기능과 실제 기능이 시각적으로 구분된다.
- 최소 창 크기에서 가로 드래그 없이 핵심 기능을 사용할 수 있다.
- 자동 테스트와 패키지 2클라이언트 테스트가 통과한다.
